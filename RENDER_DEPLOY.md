# Deploying GoProxyX on Render

One Blueprint (`render.yaml`, at the repository root) creates the whole stack on Render's **free tier**:

```
 browser
    │
    ▼
 goproxyx-frontend   static site (HTML/CSS/JS)
    │  calls, over HTTPS
    ▼
 goproxyx-gateway    Go web service: JWT auth, Redis rate limiting, reverse proxy
    │        │
    │        └──────────►  goproxyx-redis   Key Value (Redis-compatible), rate-limit state
    ├──────► goproxyx-item-service   Go web service  ──►  goproxyx-db  (Postgres)
    └──────► goproxyx-user-service   Go web service
```

| Resource | Render type | Notes |
|---|---|---|
| `goproxyx-frontend` | Static site | Free, always on, no cold start |
| `goproxyx-gateway` | Web service (Docker) | The only thing the browser talks to |
| `goproxyx-item-service` | Web service (Docker) | Applies migrations + seed data on every start |
| `goproxyx-user-service` | Web service (Docker) | Small demo API |
| `goproxyx-redis` | Key Value | Rate limiter state |
| `goproxyx-db` | Postgres | Marketplace data |

## Steps

1. **Push this folder to GitHub.** The folder that contains `render.yaml` must be the *root* of the repository (in the zip, that's `GoProxyX-main/`).
   ```bash
   cd GoProxyX-main
   git init && git add . && git commit -m "GoProxyX"
   git branch -M main
   git remote add origin https://github.com/<you>/GoProxyX.git
   git push -u origin main
   ```
2. In the [Render Dashboard](https://dashboard.render.com): **New → Blueprint**, connect your GitHub account, pick the repository.
3. Render reads `render.yaml`, shows the six resources, and asks you to confirm. Click **Apply**.
4. Wait for the deploys to finish (the first one takes several minutes; Docker builds are the slow part). The `goproxyx-item-service` logs should show `entrypoint: applying migrations...` then `item-service starting`.
5. Open the **`goproxyx-frontend`** service in the dashboard and click its URL. Pick a seller and shop.

Nothing needs to be typed in by hand: `JWT_SECRET` and `GATEWAY_SECRET` are generated by Render, the database and Redis addresses are wired in automatically, and the frontend is told the gateway's address at build time.

## What to expect on the free plan

- **Cold starts.** Free web services sleep after ~15 minutes without traffic; the next request takes up to about a minute. The gateway pings both backends when it starts, so they wake in parallel while you are still on the login screen — but the very first page load after a long idle can still feel slow. (The static frontend itself never sleeps.)
- **Postgres expires after 30 days** (then a 14-day grace period before deletion), and a workspace can have only **one** free Postgres. If you already have one, the Blueprint will fail to create this one — delete the old one or upgrade a plan.
- **Key Value (Redis) on the free plan has no persistence.** If it restarts, rate-limit counters reset. That is harmless here.
- Free web services share **750 instance-hours per month** across your workspace.

## Check it from the command line

Replace `GATEWAY` with the gateway's URL from the dashboard.

```bash
GATEWAY=https://goproxyx-gateway.onrender.com

curl $GATEWAY/health                                   # 200 (may take ~1 min if asleep)
curl $GATEWAY/auth/demo-users                          # the three demo sellers

TOKEN=$(curl -s -X POST $GATEWAY/auth/login \
  -H 'Content-Type: application/json' -d '{"user_id":"1"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

curl -H "Authorization: Bearer $TOKEN" $GATEWAY/items  # seeded marketplace items
curl $GATEWAY/items                                    # 401: no token
```

## Configuration reference

| Service | Variable | Where it comes from |
|---|---|---|
| gateway | `JWT_SECRET` | Generated by Render |
| gateway, item-service, user-service | `GATEWAY_SECRET` | Generated once, shared through the `goproxyx-shared` group |
| gateway | `REDIS_URL` | From `goproxyx-redis` connection string |
| gateway | `ITEM_SERVICE_HOST`, `USER_SERVICE_HOST` | Each backend's Render `host`; the gateway builds `https://<host>.onrender.com` |
| gateway | `PORT` | Set by Render; defaults to 3000 locally |
| item-service | `DATABASE_URL` | From `goproxyx-db` connection string |
| frontend | `GATEWAY_HOST` (or `API_BASE_URL`) | The gateway's host; `generate-config.sh` builds the URL into `config.js` at build time |

The database and Key Value instance accept connections only from inside Render (`ipAllowList: []`); to inspect the database from your own machine, change that in `render.yaml` and use the external connection string.

The gateway also accepts `ITEM_SERVICE_URL` / `USER_SERVICE_URL` (a full URL or `host:port`) and `REDIS_ADDR` (`host:port`); those are what Docker Compose uses locally.

## Security notes — please read

- **`/auth/login` is a demo endpoint.** It issues a signed token for whatever `user_id` you send, with no password. That is fine for a portfolio storefront; a real system must verify credentials before issuing anything. Remove it (and the login screen) before reusing this code for anything real.
- **The backends are public on the free plan** (Render has no free private services). They are protected by `GATEWAY_SECRET`: the gateway adds it to every proxied request and `item-service`/`user-service` reject anything without it (except `/health`). Anyone who guesses a backend's URL gets a `401 not_via_gateway`.
- **CORS is `*`.** That is safe *because* auth uses a Bearer token in a header, not a cookie. If you ever switch to cookie sessions, restrict CORS to your frontend's origin.
- **Rotating `JWT_SECRET`** (dashboard → gateway → Environment) signs everyone out.

## Troubleshooting

**The storefront says "Couldn't reach the gateway".**
The gateway is probably asleep — wait about a minute and reload. If it persists, the frontend was built with the wrong address: on `goproxyx-frontend` → Environment, add `API_BASE_URL` = the gateway's full `https://…onrender.com` URL, then **Manual Deploy → Deploy latest commit** (static sites bake the value in at build time).

**Requests return 502 / "service unavailable".**
A backend is asleep, still starting, or the gateway has the wrong address for it. Open `goproxyx-item-service` → Logs. To bypass the `host` wiring, set `ITEM_SERVICE_URL` (or `USER_SERVICE_URL`) on the gateway to the backend's full `https://…onrender.com` URL.

**item-service restarts in a loop.**
Read its logs. If you see `pq: SSL is not enabled on the server`, append `?sslmode=disable` to `DATABASE_URL`; if you see an SSL-required error, append `?sslmode=require`. If it says `postgres did not become reachable in time`, the database is still provisioning or is in a different region — every resource in `render.yaml` uses `region: oregon`.

**The Blueprint won't apply.**
Render's Blueprint page reports what it rejected. Common causes: a free Postgres already exists in the workspace (see above), or a service name is already taken by another Render user — rename it in `render.yaml` *and* in every place the naming table at the top of that file lists.

**I want it always on / properly private.**
Change `plan: free` to `plan: starter` on the services (about $7/month each, no sleeping). With paid plans you can also make `item-service` and `user-service` `type: pserv` (private services) and point the gateway at their `hostport` instead of public URLs.

## Running it locally

```bash
cd api-gateway-project
cp .env.example .env        # then edit: real JWT_SECRET, GATEWAY_SECRET, POSTGRES_PASSWORD (and the same password inside DATABASE_URL)
docker compose up --build
```

- Storefront: <http://localhost:8080>
- Gateway API: <http://localhost:3000>

The backends have no published ports locally either — they are reachable only through the gateway.
